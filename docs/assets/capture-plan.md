# Documentation capture plan

- **Purpose:** capture the real Argoscope portfolio dashboard for README documentation.
- **Source:** local app route http://127.0.0.1:<port>/ using synthetic repository observations.
- **Command/settings:** shot-scraper http://127.0.0.1:5174/portfolios/<id>/overview?window=30d --output docs/assets/README.jpg --width 1440 --height 900 --wait 3000 --quality 85. App started with ASPNETCORE_ENVIRONMENT=Screenshot so the in-memory `Seed` config seeds four synthetic repositories (example/demo-app, example/ingest-pipeline, competitor-a/rival-monitor, competitor-b/scout-board), four owner-managed package associations (DockerHub, npm, PyPI, crates.io) and runs an initial collection pass for both GitHub metrics and package adoption.
- **Artifact:** docs/assets/README.jpg (regenerated 2026-09-30; 1440×900 JPEG, quality 85). A second artifact docs/assets/adoption.jpg (regenerated 2026-09-30; 1440×900 JPEG, quality 85) shows the per-repository package adoption page. A third artifact docs/assets/decisions.jpg (regenerated 2026-09-30; 1440×900 JPEG, quality 85) shows the portfolio-level decision journal page (record form + journal list with revisions, edit, delete, and history actions). A fourth artifact docs/assets/alerts.jpg (captured 2026-09-30; 1440×900 JPEG, quality 85) shows the portfolio-level attention-alerts page (rule form, rule list with masked destinations, evaluation/delivery history). A fifth artifact docs/assets/signals.jpg (captured 2026-09-30; 1440×900 JPEG, quality 85, 98 971 bytes) shows the portfolio-level commercial-signals review queue (repository picker, state filter, source links with redacted excerpts, category/confidence suggestions, accept/reject/correct controls, audit readback). A sixth artifact docs/assets/tenants.jpg (captured 2026-09-30; 1440×900 JPEG, quality 85, 43 627 bytes) shows the tenant membership page (tenant open/create form, role explanation, owner-managed invite/role/revoke controls, migration action) against the same in-memory seed with no tenant loaded, so no account data is rendered. A seventh artifact docs/assets/billing.jpg (captured 2026-09-30; 1440×900 JPEG, quality 85, 35 953 bytes) shows the account billing page (tenant-id loader, plan/status/period/cancellation/entitlement table, provider-hosted checkout, cancel-at-period-end, reconcile and provider-event audit) against the same in-memory seed with no tenant loaded, so no account data is rendered.
- **Revision/time:** capture taken against bootstrap revision that implemented github-portfolio-momentum-mvp; re-captured on the package-adoption-metrics revision (no live GitHub or registry calls; the fake provider plus the in-memory `Seed` config populate the data). Re-captured again on the portfolio-decision-journal revision to add docs/assets/decisions.jpg; the decision form is exercised with the same in-memory seed and the journal list shows a synthetic decision with two `Unresolved` evidence references (the live app is offline, so the smoke run used the same seed and a curl POST to /api/v1/portfolios/<id>/decisions). Captured again on the portfolio-attention-alerts revision to add docs/assets/alerts.jpg: the smoke run used the same seed plus a curl POST creating an Email alert rule (`Stars momentum watch`, stars_30d ≥ 5) and a POST to evaluate it, which fired with metricValue 5185 and a visible `email-not-configured` permanent-failure delivery attempt. Captured again on the commercial-signal-review revision to add docs/assets/signals.jpg: the seeder writes three synthetic eligible sources per repository (hosted request with an intentionally embedded `buyer@example.com` address, paid-support question, plain bug) and runs the keyword classifier at startup; the smoke run additionally PATCH-reviewed the first `example/demo-app` suggestion (`HostedRequest` → corrected `EnterpriseCapability`, reviewer `owner`, note `smoke review`) so the queue shows one `Corrected` row with an audit event plus two `Pending` rows. Capture timestamp 2026-09-30T12:27Z.
- **Privacy review:** PASSED. The capture uses only synthetic repository names, synthetic package coordinates and synthetic metric data declared in src/Argoscope.Api/appsettings.Screenshot.json. No live GitHub call is performed: the fake GitHub provider is used, no token is configured, and the daily hosted service is disabled. No live package-registry call is performed: the stub HTTP adapters are replaced with in-memory `FakePackageMetricsProvider` instances per provider; the only HTTP requests originate from local synthetic data load. No real owner logins, real repository identities, real package coordinates, real metric values, or traffic details appear in the screenshot. The as-of timestamp in the UI is server time and does not reveal any real data. The decisions page does not render any package coordinates, repository names, or metric values from production — only the synthetic rationale, type, and date from the smoke test POST against the in-memory database. Evidence references on the rendered journal row carry `Unresolved` markers because the smoke references point at non-existent snapshot / package-observation ids in the in-memory store; no real id is leaked. The alerts page renders only the synthetic rule name, masked destination (`o***@example.com`), aggregate metric fact and delivery state from the smoke POSTs; the unsafe-webhook rejection probe returned 400 without sending any request, and no email or webhook delivery leaves the local host during capture. The signals page renders only synthetic issue/PR numbers, the redacted excerpt (`[redacted-email]`, confirmed in the smoke readback before capture), advisory categories with confidence and the owner-authored smoke review; the classifier is a local keyword heuristic with no network or credentials, and no GitHub write call is performed (the real provider's source listing returns empty). The tenants page renders no account data: the smoke tenant (`Smoke Tenant`/`smoke-owner`, invite `Viewer Vera` accepted as `vera`) was exercised via curl against the in-memory database and the capture shows the empty form state; invite tokens travel only in the one-time invite response and the session travels only in the HttpOnly SameSite=Strict cookie (verified in smoke response headers), never in rendered HTML. The billing page renders no account data: the smoke tenant (`Smoke Tenant`/`smoke-owner`) was exercised via curl against the in-memory database (SingleOwner creates no billing rows; billing status is 404 unconfigured) and the capture shows the empty loader state; the unsigned webhook probe returned 503 (fail-closed, no secret configured) with no state change, and no payment credential, provider secret or card data travels in any rendered HTML or API response.
- **Status:** DONE. The active OpenSpec change produced a runnable application; the screenshots above are the genuine rendered dashboard, adoption, decision-journal, attention-alerts, commercial-signals, tenant-membership, and account-billing views. Future changes to the UI must regenerate this artifact and re-record the timestamp and privacy review.
